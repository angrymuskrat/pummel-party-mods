# Pummel Party mods — правила работы

Цель проекта: несколько тематических карт (досок) для Pummel Party и под каждую — набор тематических мини-игр. Основной путь — официальный Mod Editor (Steam Workshop, с обновления 1.12.1): сцены и логику собирают мышкой, кода нет. Claude здесь — геймдизайнер, справочник по редактору, генератор ассетов и разборщик логов. Код появляется только на неофициальном пути BepInEx, и только по явному решению пользователя.

## 1. SOP

1. **Коммитить только по прямому требованию.** Завершённая задача — не разрешение на `git commit`. Push, публикация в Workshop, запуск игры, установка BepInEx в папку Steam — тоже только по запросу.
2. **По окончании сообщать об изменённых файлах и выполненных проверках**, оставляя изменения незакоммиченными.
3. **Скиллы — по согласованию.** Классифицировать задачу по разделу 2, предложить набор одним блоком (`Класс: B. Предлагаю: … Пропускаю: … Ок?`), вызывать после согласия. Это правило выше автозапуска из `using-superpowers`, `nav-brief`, `nav-workflow`. Тривиальное (вопрос, однострочная правка, чтение файла) — без скиллов и без предложения. Явный `/<skill>` — уже согласие.
4. **Проектировать только из того, что реально есть в редакторе.** Источник правды — `.claude/skills/pummel-party-mod-editor/reference/`. Если вики молчит — так и писать, не выдумывать действия и параметры.
5. **Документация равна коду.** Утверждение о компоненте, действии, формате или пути проверяется по `reference/` (со ссылкой на страницу вики) или по игровым файлам до того, как текст считается готовым.
6. **Ассеты генерировать воспроизводимо:** скрипт лежит рядом с результатом в `packs/<theme>/assets/`.
8. **Моды собирать кодом.** Для каждой мини-игры `build_mod.py` рядом с `DESIGN.md`, на базе `tools/pmgen.py`; вывод в `WorkshopMods`. Редактор — для плейтеста, скриншотов и публикации. Новые компоненты и действия добавлять в `pmgen.py` по `scene-format.md`.
7. Игра установлена: `C:\Program Files (x86)\Steam\steamapps\common\Pummel Party\` (Steam, проверено 2026-10-21). Папка данных — `PummelParty_Data` без пробела. Бэкенд Mono, Unity 2021.3.45f2. Проекты редактора — `%USERPROFILE%\AppData\LocalLow\Rebuilt Games\Pummel Party\WorkshopMods\`.

## 2. Классификатор задач → скиллы

| Класс | Сигналы | Цепочка | Не брать |
| --- | --- | --- | --- |
| **A. Новый пак / доска / мини-игра** | «придумай», «сделай карту», «мини-игра про…» | `pummel-party-themed-pack` → при неясной теме `grilling` → спецификации | `brainstorming` (его заменяет `grilling`), `writing-plans` |
| **B. Разложить идею на события и действия редактора** | «как это сделать в редакторе», «какие действия нужны» | `pummel-party-mod-editor` → `simplest-fix-first` (самая простая цепочка, которая даёт механику) | — |
| **C. Ассеты** | модель, текстура, звук, .obj | без скиллов: скрипт генерации + `ASSETS.md`; правила импорта из `pummel-party-mod-editor/reference/editor-workflow.md` | — |
| **D. Отладка в редакторе** | скриншот Log Window / Mod Validator, «не работает», «не синхронизируется» | `deep-investigation` → `simplest-fix-first`; объяснение — `feynman` | `systematic-debugging` |
| **E. Код-мод** | предметы, правила доски, боты, «редактор не умеет» | `pummel-party-bepinex` → `test-driven-development` → `pre-ship` | `backend-endpoint` и прочие navigator-скиллы |
| **F. Стресс-тест дизайна** | «прожарь», «проверь план», «что не так с механикой» | `grilling` | — |
| **G. Внешнее исследование** | «что известно о», аналоги, форумы, новые версии вики | `nav-deep-research` или агент `web-fetch` | — |
| **H. Объяснение / материалы** | «объясни просто», описание для Workshop | `feynman` | — |
| **0. Тривиальное** | вопрос, правка строки, чтение | без скиллов | — |

## 3. Структура репозитория

```
.claude/skills/
  pummel-party-mod-editor/   # справочник по редактору + reference/ (выжимка вики)
  pummel-party-themed-pack/  # процесс: тема → доска → мини-игры → ассеты
  pummel-party-bepinex/      # неофициальный код-путь
  grilling/ simplest-fix-first/ feynman/ deep-investigation/ pre-ship/   # общие, перенесены из synapse
packs/<theme>/               # по паку на тему: PACK.md, board/, minigames/ (DESIGN.md + build_mod.py), assets/
tools/pmscene.py             # парсер/сериализатор MainScene.scene и .pfab (PMH)
tools/pmgen.py               # генератор модов: сцена, префабы, ассеты с .pmeta, материалы, ModSettings
mods/<name>/                 # только для BepInEx-плагинов
```

## 4. Открытые вопросы

- Генерация модов кодом подтверждена плейтестом (2026-10-21): Ticket Rush Gen собран `build_mod.py`, в игре работают предметы, триггеры, спавнеры, материалы, таймер. Новые мини-игры делать через `tools/pmgen.py`, а не мышкой.
