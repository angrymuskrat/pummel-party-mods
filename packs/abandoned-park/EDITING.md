# Как изменить существующую игру Rusted Park

У мини-игры есть три разных места, где видна её версия. **DESIGN.md** описывает правила для человека. **build_mod.py** собирает сцену, настройки и ассеты. **WorkshopMods** содержит проекты, которые открывает Mod Editor. Поэтому смена числа в описании сама по себе не меняет игру, а пересборка в папку с ручными правками может их перезаписать. Найти спецификацию, исходник и следующую задачу можно в [карте всех игр](WIKI.md).

## Пример · изменить цену золотого шара

Допустим, на тесте Balloon Pop все бросают обычные шары ради золотого. Хотим проверить гипотезу: при награде 2 вместо 3 у обычных шаров снова есть смысл. Это пример эксперимента; в текущей основной игре золото стоит 3.

1. **Найти, откуда берутся очки.** В [сборщике Balloon Pop](minigames/balloon-pop/build_mod.py) обычные шары вызывают `target(..., delay=3.5)`, золотой — `target(..., points=3, delay=6, ...)`. В [общей функции target](minigames/reserve_common.py) награда по умолчанию равна 1. Попадание начисляет переданное количество игроку, попавшему по шару. Следующее ожидание управляет возвращением шара.
2. **Изменить только нужный вызов.** Для эксперимента поставить `points=2` у `GoldBalloon`. Сохранить интервал 6 секунд и обычную награду 1. В описании для загрузочного экрана того же сборщика заменить «Gold is worth three points» и в DESIGN записать ожидаемый результат. Если одновременно менять интервал и цену, по матчу будет трудно понять, что повлияло на выбор.
3. **Собрать под отдельным именем.** Ниже команда именно для Balloon Pop. Запускать из корня репозитория в PowerShell, на машине с установленной игрой. Временная папка создаётся при каждом запуске. И проект, и сгенерированные планы окажутся там.

```powershell
$projectPath = @'
from pathlib import Path
from tempfile import mkdtemp
from runpy import run_path

out = Path(mkdtemp(prefix="rusted-balloon-"))
build = run_path("packs/abandoned-park/minigames/balloon-pop/build_mod.py")["build"]
project = build(name="Balloon Pop - Test", workshop=str(out), output_dir=out)
print(project)
'@ | python -B -
if ($LASTEXITCODE -ne 0) { throw 'Сборка Balloon Pop завершилась с ошибкой' }
python -B tools/pmscene.py roundtrip "$projectPath/Data/MainScene.scene"
```

4. **Понять результат проверки.** `OK` означает, что парсер прочитал сцену и записал обратно те же байты. Для проверки поведения скопировать полученную папку проекта в свободную папку `WorkshopMods/Balloon Pop - Test`, открыть именно этот проект в Mod Editor и выполнить **Mod Validator**. Если тестовый проект с таким именем уже редактировался, сохранить его отдельно или собрать под новым именем.
5. **Сыграть проверяемый случай.** Ударить обычный шар, затем золотой. Для экспериментальной цены счёт меняется 0 → 1 → 3. Другой игрок при этом очков не получает. Ударить золотой одновременно с клиента и хоста, сверить единственную выплату, доиграть и запустить второй матч. Для решения о балансе записать, куда двинулись игроки при следующем появлении золота.
6. **Зафиксировать решение.** В карточке игры записать «испытано», версию сборки, дату и наблюдение. Заполнить строку [таблицы плейтеста](PLAYTEST_RESULTS.csv). При удачном результате перенести изменение в основной сборщик и обновить строку [вики](WIKI.md); при неудачном сохранить причину отказа в DESIGN. Резервная копия установленного проекта сохраняет ручные настройки, исходную сцену и служебные данные Workshop.

## Где искать правку в других играх

| Что меняется | Откуда начать | Что проверить после сборки |
|---|---|---|
| Правило одной из первых восьми игр | Индивидуальный `build_mod.py` из карты. Для версии с оформлением от 20 ноября брать сборщик, подключающий `core_style.py`, вместе с [модулем оформления](assets/art-direction/core_style.py). | Прежняя механика и свет. При изменении расстановки осмотреть новый план сверху и оба разреза. Подбор и видимость цели проверить с игровой камеры. |
| Одна из пяти резервных игр | Индивидуальный сборщик задаёт объекты и числа, [reserve_common.py](minigames/reserve_common.py) — общие мишени, оружие и завершение сборки. | При правке общего поведения проверить всех его потребителей. Аргументы CLI для этих пяти игр — имя и родительская папка проектов; по умолчанию планы пишутся рядом со сборщиком. |
| Карточки, правильные ответы, котёл | Открыть обёртку игры и пройти в [expansion_common.py](minigames/expansion_common.py): `build_quiz` или `build_boiler`. Материал заданий создаёт [генератор ассетов расширения](assets/expansion/generate_assets.py). | Проверить весь банк на однозначность ответов, один выбор и момент начисления. [Проверка первой шестёрки](minigames/check_expansion.py) принимает родительскую папку со всеми шестью проектами под штатными именами. |
| Часы, лабиринты, распродажи, рейсы, сигналы, ловушки | У шести обёрток общий [finale_common.py](minigames/finale_common.py). Например, `run_closing` собирает поездки, `run_traps` — площадки с пультами. Материалы и данные — [генератор финальной партии](assets/finale/generate_finale.py). | Проверить границы окна, повторный вход и сброс состояния. [Проверка второй шестёрки](minigames/check_finale.py) также ожидает всю группу. |
| Модель, текстура, звук или свет | Использовать [каталог ассетов](assets/ASSETS.md) и [пять профилей](ART_DIRECTION.md). При изменении ресурса править его генератор. Для проверки импорта есть [эталонные сцены](assets/art-direction/build_references.py). | Сравнить игровой кадр до/после в одинаковом ракурсе. Проверить UV, надписи, дальнюю цель и уменьшенный вид. При сборке поверх существующего проекта `pmgen` сохраняет имеющееся освещение по умолчанию. |
| Searchlights или Bumper Cars | В таблице вики даны ревизии с исходниками. Например, `git show abb6ec3:packs/abandoned-park/minigames/searchlights/build_mod.py` покажет сборщик без переключения ветки. Посмотреть также `git show --stat abb6ec3` или `git show --stat 104a207`: архивная версия использует свои ассеты и изменения генератора. | Сделать отдельную сборку, сравнить сцену, компоненты, материалы и поведение с копией установленного проекта. Только после сверки выбирать основу для изменений. |
| Mascot Carts или Barrel Bends | Узнать номер версии в имени установленного проекта. Для V3 в репозитории есть [команды сборки и проверки](minigames/mechanic-prototypes/PLAYTEST.md), [исходные ассеты](assets/mechanic-prototypes/ASSETS.md) и [контрольные суммы](minigames/mechanic-prototypes/SNAPSHOT_V3.json). У этих двух CLI один аргумент — папка назначения. | Сверить версию в отчёте установки с проектом. У маскотов проверить выбранный номер, верный номер и место на табло. У бочек — видимый контакт и проходимость поворотов. |
| Доска | Открыть [паспорт Rusted · Midway](board/BOARD.md). Рабочая основа — установленный проект редактора. | Сохранить его копию, проверить маршрут броском кубика, эффект каждой специальной клетки и полный матч на доске. |

**После правки общего генератора.** [pmgen.py](../../tools/pmgen.py) создаёт проекты, [pmscene.py](../../tools/pmscene.py) читает и записывает их бинарные сцены. Значения компонентов и действий сверять по [разбору формата](../../.claude/skills/pummel-party-mod-editor/reference/scene-format.md) и [каталогу редактора](../../.claude/skills/pummel-party-mod-editor/reference/logic-catalog.md). Для всех 27 установленных игр есть команда `python -B tools/audit_playtest.py`. Она ожидает полный набор с именами из каталога. Порядок игровых и сетевых проверок — в [чеклисте](PLAYTEST.md).
